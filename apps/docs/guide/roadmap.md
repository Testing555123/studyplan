# 学习路线图

## 阶段切法：先横切，后纵切

全栈项目有两种常见的推进方式，各有致命缺点：

- **全程横切**：先把前端全部做完（用假数据），再做后端。
  → 前一个月看不到"全栈"的感觉，后期联调集中爆雷。
- **全程纵切**：每个阶段做一个完整功能，前后端一起写。
  → 你还没搞懂路由和数据层，就要硬写业务逻辑，容易塌。

**本项目采用混合切法**：前 4 个阶段横切打地基，第 5 阶段起改纵切。

```text
【横切 · 阶段 1-4：先把地基打通】

   阶段 1 工程地基 ──┬──▶ 阶段 2 前端原型（mock 数据）──┐
   monorepo + TS     │                                  ├──▶ 阶段 4 首次联调
                     │                                  │    列表 / 详情接真实接口
                     └──▶ 阶段 3 后端 + 数据库 ─────────┘
                          Post CRUD + MongoDB Atlas

【纵切 · 阶段 5-8：每个功能点前后端一次做穿】

   阶段 4 ──▶ 阶段 5 认证与发帖 ──┬──▶ 阶段 6 评论 / 点赞 / 标签 ──┐
                                  │                                ├──▶ 阶段 8 测试与上线
                                  └──▶ 阶段 7 AI 摘要与标签 ──────┘
```

> **关于图示**：本文档全部使用 ASCII 框图而不是 Mermaid。
> 原因是 VitePress 原生不渲染 Mermaid，需要额外插件与运行时依赖。
> 对一本"要在编辑器里随时翻看"的电子书来说，ASCII 图在
> GitHub、编辑器、终端里显示完全一致，且不会因为依赖升级而失效。

为什么前 4 个阶段是横切？

因为**地基必须先通**：`packages/shared` 的契约、Nuxt 的页面结构、
NestJS 的模块划分、数据库的连接方式——这些一旦定下来，
后面每个功能点都只是"照着同一套模式再写一遍"。
地基不通就上业务，等于在流沙上盖楼。

## 8 个阶段的目标与验收标准

每个阶段的验收标准都是**可执行、可肉眼确认**的，不接受"大概懂了"。

### 阶段 1 · 工程地基与 TypeScript 起步

| 项 | 内容 |
| --- | --- |
| 学什么 | monorepo 是什么、pnpm workspace、TypeScript 最小语法集（类型注解、interface、可选属性、联合类型）、`tsconfig` 各字段含义、ESLint/Prettier 为什么需要 |
| 动手 | 建 monorepo；写出共享契约；Nuxt 首页骨架；后端 `/api/health` 能返回 JSON |
| 验收 | ① `pnpm install` 无报错；② `pnpm dev:api` 后访问 `http://localhost:3000/api/health` 有 JSON；③ `pnpm dev:web` 后 `http://localhost:3001` 有页面；④ `pnpm dev:docs` 后 `http://localhost:3002` 有电子书 |
| 笔记 | `stages/stage-1.md` |
| 练习 | `exercises/stage-1.md` |

## 每阶段固定交付三样东西

1. **可运行的最小实现** —— 不接受"写完了但跑不起来"；
2. **笔记** —— AI 出结构与初稿，**核心概念必须你自己用自己的话重写一遍**，并记录踩坑；
3. **规划小练习** —— 看着下一个阶段的功能清单，自己写"三步拆解 + 工时估算"，再对照修正。

> 第 2 条和第 3 条才是这个项目真正的产出。
> 代码是素材，笔记是你的理解，规划练习是你的能力。
